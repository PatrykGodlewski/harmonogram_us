# Programme sessions (F33) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline). Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** An event's programme ("harmonogram") can be divided into sessions — like Indico's timetable sessions — each with a title, theme (description and colour), location and start–end; organisers go into a session to edit its programme and copy a session to another time and place.

**Architecture:** New table `agenda_sessions` (event-owned); `agenda_items.session_id` (nullable: items outside any session stay, e.g. opening, breaks). Items of a session lie within its start–end. Copying a session creates an independent session with the items shifted by the same amount (no link afterwards). The admin event page lists sessions and loose items; a session has its own admin route with the existing programme editor scoped to it. The public event page groups the list by session and colours calendar blocks by session. Registration is unchanged: event-level plus per-item seats (F27).

**Tech Stack:** Drizzle/Postgres, TanStack Start server functions, TanStack Router/Form/Query, React, Paraglide, Playwright, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-produkt-design.md` — new F33 „Sesje w harmonogramie”. User (22.11): "event should have groups, groups can group agenda … groups can be copied and set time start-end, going in to group we edit agenda, groups are location specific with specific theme" with the example „Śląski Festiwal Nauki”: one lectures session, two exercise sessions with the same programme in two locations; "in indico it is called Harmonogram so similar to it"; chose to build the proposal (sessions, go in, copy with new start and location, copies independent, registration unchanged).

## Decisions

- Name: „Sesja” / "Session" (the word „grupa” already means teacher group registration, F26; Indico uses „sesja”).
- `agenda_sessions`: `id` text uuid, `event_id` → events (cascade), `title` (1–200), `description` (≤ 2000, null), `color` text CHECK in `slate|blue|green|amber|rose|violet` (default `blue`), `location_id` → event_locations (null), `starts_at`, `ends_at` (CHECK ends > starts), timestamps; index `(event_id, starts_at)`.
- `agenda_items.session_id` → agenda_sessions, **ON DELETE CASCADE**: deleting a session deletes its programme (confirm dialog names the number of items); registrations go with the items, as when deleting an item today.
- Rules (domain errors): an item in a session must start and end within it (`ITEM_OUTSIDE_SESSION`); a session's new times must still contain its items (`SESSION_ITEMS_OUTSIDE`); a session of another event is `SESSION_NOT_FOUND`.
- New items in a session start with the session's location; the shown location of an item is its own, else its session's.
- Copy (`copyAgendaSession`): inputs `startsAt` (required), `locationId` (optional; default: the source's), `title` (optional; default: the source's). Same duration; items copied with title, description, duration, offset from session start, seat limit, registration flag, speakers and links; an item whose location equalled the source session's location takes the copy's location. Not copied: registrations, files. One transaction.
- Duplicating an event (F3) copies its sessions and keeps items in their (copied) sessions.
- Admin: event page programme section shows sessions (colour bar, title, time, location, number of items; „Otwórz”, „Kopiuj”, „Edytuj”, „Usuń”) and loose items; „Dodaj sesję”. Session route `/events/$eventId/sessions/$sessionId`: header with session details, „← Wróć do wydarzenia”, the programme editor limited to the session (adding an item puts it in the session). Phone first (360 px).
- Public: list view groups by session (heading with colour bar, title, time, location, description), loose items in time order between them; calendar view colours each item by its session and shows a session legend. Polling (15 s) brings session changes like any other event data.
- Out of scope: per-session registration or seat limits, session conveners/managers, linked (synchronised) copies, moving items between sessions by drag.

- A session from another event cannot be used, edited, copied or deleted through this event's id (permission checks use the session's own event).
- Editing a session's times or an item's times cannot leave items outside their session.
- Copy across a DST change keeps wall-clock times (shift in event time zone, like event duplication).
- Deleting a session with registered people: the confirm says what is lost; seat counts stay consistent (cascade through existing item deletion paths).
- The public list with only loose items looks exactly as before (no empty session headings).
