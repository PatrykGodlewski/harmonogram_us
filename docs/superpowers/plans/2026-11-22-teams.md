# Microsoft Teams meetings for online events (F23) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** For an online or hybrid event, the organizer creates the Teams meeting with one click in the panel; its join link becomes the event's meeting link, which only registered people see.

**Architecture:** A small Microsoft Graph client in `@repo/api/teams` gets an app-only token (client credentials) and calls `POST /v1.0/users/{organizer}/onlineMeetings` (subject, start, end; Graph returns `joinWebUrl`). An admin server function creates the meeting and stores the link with a conditional update (only while the event has no link), so a double click or a second organizer never replaces a link. The existing rules keep the link private: the public reads never carry it; registered people get it on the event page.

**Tech Stack:** TanStack Start server functions, Drizzle, fetch, Paraglide, Playwright; a node stand-in for Graph in the e2e stack.

**Spec:** `docs/superpowers/specs/2026-11-19-produkt-design.md` (F23: „Automatyczne spotkanie u dostawcy uczelni (Microsoft Teams). Gotowe, gdy dla wydarzenia online powstaje spotkanie (atrapa Graph w testach), a link jest widoczny dla zapisanych”). Decisions are the architect's (user delegated decisions). Graph API checked with Context7 (`/microsoftgraph/microsoft-graph-docs-contrib`, application-post-onlinemeetings).

## Decisions

- Configuration (all server-only, feature off unless the first four are set): `TEAMS_TENANT_ID`, `TEAMS_CLIENT_ID`, `TEAMS_CLIENT_SECRET`, `TEAMS_ORGANIZER_ID` (Entra object id or UPN of the account the meetings belong to); `TEAMS_LOGIN_URL` (default `https://login.microsoftonline.com`) and `TEAMS_GRAPH_URL` (default `https://graph.microsoft.com`) exist for the e2e stand-in. University IT grants `OnlineMeetings.ReadWrite.All` (application) and an application access policy for that account.
- One click, not a background job: the organizer sees the link (or the error) at once, and publishing still requires a link, as today. Offered where the link is entered: the publish checklist's link row and the event edit form (existing events), only for online/hybrid events and only when Teams is configured.
- Meeting: subject = event title, start = event start, end = effective end. No update or delete later: a Teams join link keeps working whatever the times, and the organizer can change or remove the link like any other.
- Errors: Graph or token failure → `TEAMS_FAILED` (message „Nie udało się utworzyć spotkania w Teams…”); not configured → `TEAMS_NOT_CONFIGURED`; on-site event → `TEAMS_NOT_ONLINE`. The event keeps no partial state.

## Review Focus

- The client secret and tokens never reach the browser, logs or error messages.
- Only managers of the event can create a meeting (not check-in helpers).
- A link already set (manual or Teams) is never replaced by a click.
- The link stays hidden from the public site and from people not registered.
- Graph responses without a usable `joinWebUrl` (missing, not https) are refused, not stored.
