# F16 Events from Indico — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Events from the university's Indico appear read-only in the campus list and calendar feed, marked "From Indico" and linking to the original, with no way to register.

**Architecture:** The worker fetches Indico's HTTP export API (`/export/categ/{ids}.json`) every 30 minutes and at start-up, and mirrors the result into an `indico_events` table. The table is separate from `events`, so no registration, seat-count, panel or Electric path can ever touch an imported event. The public list server function merges the first `limit + 1` local events with the first `limit + 1` matching Indico events by date. The campus ICS feed appends Indico entries.

**Tech Stack:** Drizzle/Postgres, pg-boss, Zod, TanStack Start/Query, Vitest, Playwright, a Node mock of the Indico export API for e2e.

**Spec:** [product spec F16](../specs/2026-11-19-produkt-design.md): "Import do odczytu wydarzeń z uczelnianego Indico, z linkiem do oryginału; nie można się na nie zapisać." Acceptance: "wydarzenie z testowego eksportu Indico jest w kalendarzu z oznaczeniem i linkiem". Rule K: "integracje zewnętrzne (…, import z Indico) od początku są za prostym wspólnym interfejsem". The owner delegated design calls to Claude (21 November 2026).

## Design (short)

**Approaches considered:**
- **(a) Rows in `events` with `source = 'indico'`:** filters, the details page and feeds would come for free. But every write path would need a guard: registration, guests, groups, agenda items, panel edits, seat counts and Electric shapes. One missed guard lets people register for an Indico event.
- **(b) Separate mirror table, merged into the list (chosen):** imported events cannot reach any write path by construction.
- **(c) A Rust import service:** the work is a few hundred rows of I/O every 30 minutes. A new service would add deployment cost with no performance gain.

**Configuration** (`@repo/env`; import is off unless both of the first two are set):
- `INDICO_URL`: the base URL.
- `INDICO_CATEGORY_IDS`: e.g. `12,34`.
- `INDICO_API_TOKEN` (optional): sent as `Authorization: Bearer`. The export returns whatever the token's user may see, so the docs say to use no token, or the token of an account with public access only.

**Fetch window and data:**
- Window `from=-30d&to=+365d`, `limit=1000`.
- Stored fields: `id`, `title`, `starts_at`, `ends_at`, `location`, `room`, `url`.
- The description is not stored. It is HTML, and the link carries the details.

**Interface (rule K):** `fetchIndicoEvents(config, fetchImpl): Promise<ImportedEvent[]>`. A second source would implement the same function shape.

**Mirror and failure handling:**
- Each sync replaces the table contents in one transaction.
- A failed fetch (HTTP error, timeout of 10 s, invalid JSON) leaves the previous mirror and logs the error.
- An empty but valid result empties the table.

**Link and times:**
- The link is built as `{INDICO_URL}/event/{id}/` (id must be digits), never taken from the feed, so a feed cannot inject a `javascript:` or foreign link.
- Times: Indico gives local `date` + `time` + `tz`. These are converted to UTC in TypeScript. An unknown time zone skips that event.

**List behaviour:**
- Search (title) and the date filter apply to Indico events too.
- Type, place, unit or format filters exclude them, because Indico events carry none of these.
- Sorting matches the list's order.

**Card:**
- Title links to Indico (same tab).
- Date line, "Z Indico" / "From Indico" badge, location and room.
- No registration button and no seat count.

**Calendar feed:** the campus ICS feed includes upcoming Indico events, with UID `indico-{id}` and URL = the Indico link.

## Global Constraints

- AGENTS.md rules: TDD with `[F16]` Playwright test written first; phones first (360 px); UI text in `pl.json` and `en.json` + `pnpm messages:compile`; no barrels; Biome; `@repo/env` only; migrations via `pnpm --filter @repo/db db:generate`.
- No unbounded reads: list reads take `limit + 1`; the feed reads at most 500.
- Never write imported events into `events` or seat-count tables.

## Review Focus

1. **Indico unreachable or returning junk:** the previous events stay listed; the worker keeps running. Owned by Task 2 (fetch throws) and Task 3 (sync keeps the mirror on error).
2. **DST:** an event at 10:00 Europe/Warsaw on 2026-03-29 (the day clocks change) is stored as 08:00 UTC. Owned by Task 2.
3. **A feed URL pointing elsewhere or a non-numeric id:** the event is skipped and no foreign link is shown. Owned by Task 2.
4. **Pagination with both sources:** "show more" never duplicates or drops an event, and `hasMore` is true when only Indico events remain. Owned by Task 4 (`mergeByDate` unit test).
5. **Filters:** a type filter hides Indico events, and search finds them by title. Owned by Task 4 (unit test).
